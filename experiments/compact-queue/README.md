# Queue history responsiveness and compact storage

Before this patch, `QueueHistoryRepository.saveQueue` traversed the complete Track graph and materialized its JSON string on the calling thread before launching IO. Queue replacement/archive call sites run on Main. Expanding a history card also decoded Track[] on Main after its database read returned. Large queues can therefore spend their full JSON serialization/parsing time blocking the UI.

Now only list membership and lightweight metadata are captured synchronously. Encoding, insert and trimming run in the IO coroutine under a FIFO write queue, so only one encoder workspace runs at once. Pending saves retain their shallow queue snapshots if submissions outpace encoding; this bounds simultaneous encoder workspaces, not total backlog memory. Expanded-card decode uses Default. History rows use versioned `kittytune-queue:gzip:1:` TEXT containing fast GZIP/Base64, written directly from Gson without a complete raw JSON String. Decode reads directly from the decompressor. No fields, order, duplicate tracks or quality settings are removed; image/audio data are unchanged.

Legacy plain JSON rows remain readable and are not rewritten. No database schema migration is needed, and the lightweight summary projection stays unchanged. **Downgrading to an older app version cannot restore newly compressed history rows.** Older rows remain compatible; backup of the database carries the versioned rows intact. This format is private to history, not playback persistence, likes, downloads or exported playlists. It does not reduce the live queue/Track graph itself or global idle RAM.

Run `python experiments/compact-queue/run.py --output verification/compact-queue` with JDK 21. Optional `--java-home` and `--dependency-cache` reuse local tools. It compiles actual app models, Gson adapters and codec. A small SpotifyRepository ID-helper shim satisfies unused model display helpers on the desktop JVM; full Android tests use the real app dependencies. Standalone Gson is 2.11.0 (Retrofit 3 converter's baseline); Android verification uses the project's resolved version.

Tests cover legacy rows, complete real Track graphs, ordering/duplicates, optional fields, emoji and isolated UTF-16 surrogates, invalid/truncated payloads and a large roundtrip. Gated coroutine tests cover an in-flight save followed by Clear All/new save, and continued delete/save processing after a failed write. All history writes are ordered, so a pending snapshot cannot reappear after Clear All completes. The codec throws on invalid data; the repository retains its existing empty-history fallback.

The initial codec at `65c641bb` regressed allocation/time: forwarding Gson's tiny writes directly through surrogate scanning and UTF-8 encoding creates encoder wrappers per token. The corrected writer places a reusable 32,768-character buffer **before** that work and uses 32 KiB gzip buffers. Reads also batch decoded characters before Gson consumes them. This changes batching only: the v1 payload format, surrogate preservation, legacy reader, IO write queue and UI dispatching stay unchanged.

Five fresh JVMs compare raw JSON, a frozen copy of the initial unbuffered codec, and the corrected buffered codec with actual app Track objects and synthetic lean, rich and high-entropy metadata (500/5000/20000 tracks). Six rounds rotate execution order after warmup, reversing the order for decode. The frozen codec is confined to experiments, and cross-decoding in both directions verifies v1 compatibility. CSV reports payload characters/UTF-8 bytes, encode/decode time, and thread-allocated Java bytes via ThreadMXBean. Allocation totals are not peak retained heap or Android RAM. Native zlib workspace and unrelated app work are excluded. Gson remains necessary to reconstruct all Track objects, and compression can add CPU time; publish those costs alongside storage/allocation reductions. Offloading removes serialization from the caller but does not make total background work disappear. Device frame timing, peak RAM, disk I/O and whole-app speedups remain unmeasured.
